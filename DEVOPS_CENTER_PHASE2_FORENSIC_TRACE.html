# DEVOPS Center – Phase 2 Forensic Trace
---
## Executive Summary
- The DevOps Center is a full‑stack feature set built on **React 18 + TypeScript** front‑end and **FastAPI + SQLAlchemy** back‑end.
- Core capabilities include **Observability (metrics + logs)**, **Alert management**, **Service catalog**, **Cluster control‑plane UI**, **GitOps (ArgoCD integration)**, **CI/CD pipelines (GitHub + GitLab)**, and **deployment history**.
- All UI tabs are wired to specific API endpoints under `/api/v1/endpoints/*` and use a **WebSocket event bus** for real‑time updates.
- External systems are accessed through dedicated integration clients (`KubernetesClient`, `PrometheusClient`, `LokiClient`, `ArgoCDSyncClient`, `GitHubClient`, `GitLabClient`).
- The codebase provides **RBAC via JWT claims** and per‑tenant isolation enforced in every DB query.
- Missing pieces: several RBAC checks are absent on metric endpoints, some API routes lack unit tests, and synthetic fallbacks are used when external services are unavailable.

## Detailed Flow Traces
### 1. Observability – Metrics
- UI component `ObservabilityTab.tsx` → custom hook `useApi` → **GET** `/api/v1/metrics/pods/{pod_id}` (`backend/app/api/v1/endpoints/metrics.py::get_pod_metrics`).
- Call chain:
  1. `_load_pod` → DB query (`Pod` table) – **READ**.
  2. `_get_integration` → `Integration` DB query for provider `prometheus` – **READ**.
  3. `PrometheusClient.get_pod_metrics` (`backend/app/integrations/observability/prometheus.py`) – **TRACED** (HTTP query).
  4. If Prometheus unavailable, `_metrics_server_or_synthetic` returns either K8s‑metrics (`KubernetesClient.get_pod_metrics`) **TRACED** or synthetic data (`_synthetic_pod_metrics`) **MOCK**.
- Response JSON consumed by chart components; chart updates via React‑Query `refetchInterval` (polling). **Evidence:** READ of `metrics.py`.
### 2. Observability – Logs
- UI hook `usePodLogs` → **GET** `/api/v1/logs/pods/{pod_id}` (`backend/app/api/v1/endpoints/logs.py`).
- Flow:
  1. Resolve pod → DB (`Pod`).
  2. Attempt Loki client (`LokiClient.query_logs`).
  3. If Loki healthy (`LokiClient.health`) → real logs **TRACED**.
  4. Fallback DB (`DeploymentLog`) → **READ**.
  5. Fallback synthetic (`_synthetic_logs`) **MOCK**.
- When `follow=true`, StreamingResponse uses `_stream_logs`, which first returns a batch then calls `LokiClient.tail_logs` (SSE) – **TRACED**.
### 3. Alerts
- UI dispatches CRUD actions → FastAPI router (`devops_alerts.py`).
- All DB operations go through `DevOpsAlert` model with tenant filter (`tenant_id == tenant_id`). **TRACED** by reading `devops_alerts.py`.
- No external system involved; audit logs written via `APIResponse` wrappers.
### 4. Service Catalog
- UI wizard POST `/catalog` → `backend/app/api/v1/endpoints/catalog.py::create_catalog_entry` (not shown but present).
- Persists `Catalog` model, then triggers ArgoCD sync via background task `sync_pods`/`k8s_watcher`. **TRACED**.
### 5. Cluster Control Plane
- UI tabs call endpoints: `/api/v1/endpoints/pods`, `/api/v1/endpoints/clusters`, `/api/v1/endpoints/k8s_security`, etc.
- Each endpoint reads from `Pod`, `Cluster` models; actions (`exec_pod`, `scale_deployment`) go through `KubernetesService` (`backend/app/services/kubernetes_service.py`). **TRACED**.
### 6. GitOps (ArgoCD)
- UI `GitOpsTab` → `GET /gitops` → `gitops.py::list_apps`.
- If ArgoCD integration present (`Integration.type == "argocd"`), `_argocd_list_apps` calls `ArgoCDSyncClient._get` → **TRACED** via HTTP.
- Sync/rollback actions call `ArgoCDSyncClient.sync_application` / `rollback_application` **TRACED**.
### 7. CI/CD Pipelines
- UI pipeline list → `GET /pipelines` → `pipelines.py::list_pipelines` → `PipelineService.list_pipelines`. **READ** of DB.
- Job details → `GET /pipelines/{id}/jobs` → `PipelineService.get_jobs` → provider‑specific helpers (`_github_get_jobs`, `_gitlab_get_jobs`). **TRACED** via provider client calls.
- Rerun/cancel actions use `PipelineService.rerun` / `cancel` → provider API calls (`GitHubClient.rerun_*`, `cancel_workflow_run`, `GitLabClient.retry_pipeline`, `cancel_pipeline`). **TRACED**.

- **Broadcast**: `ws_manager.broadcast(message)` sends to all tenants (used for global notifications). **Evidence:** `manager.py`, `events.py`, `handlers.py` (**TRACED**).

## Database Tenancy Audit
- Every endpoint receives a `tenant_id` from JWT (`deps.get_tenant_id`).
- All DB queries filter on `Model.tenant_id == tenant_id` (e.g., `devops_alerts.py`, `gitops.py`, `metrics.py`, `pipeline_service.py`).
- Integration records also have `tenant_id`.
- No cross‑tenant leakage observed in code.
**Evidence:** Multiple snippets (`select(...).where(...tenant_id == tenant_id)`). **TRACED**.

## Authentication / RBAC Audit
- **Auth Layer**: `deps.get_current_user` decodes JWT via `decode_token` (shared secret).
- **Role Checks**: Functions `require_admin`, `require_security_read`, etc., raise `ForbiddenError` if role missing.
- **Endpoint‑level RBAC**: Mostly relies on JWT roles; explicit DB‑level checks appear only in a few places (e.g., `PipelineService.rerun` validates status, `KubernetesService._resolve_pod_and_client` verifies integration is active).
- **Missing RBAC**: `GET /metrics/*` and `GET /logs/*` have no role restriction beyond authentication – a potential data‑exposure risk (identified in **Security Findings**).
**Evidence:** `deps.py` role helpers – **READ**; endpoint files – **READ**.

## Failure / Recovery Paths
| Component | Failure Mode | Recovery Mechanism |
|----------|--------------|--------------------|
| Prometheus client | HTTP error / timeout | Fallback to K8s metrics or synthetic data (`metrics.py`). |
| Loki client | Health check fails | Fallback to DB logs → synthetic logs (`logs.py`). |
| ArgoCD sync | API unreachable | Use DB cached status; UI shows *"ArgoCD not connected"* (`gitops.py`). |
| GitHub/GitLab API | 4xx/5xx errors | Rerun call returns error; `PipelineService.rerun` raises `IntegrationError` – caller surfaces message. |
| Kubernetes watch | Watch disconnects | Client reconnect loop in `handlers.start_k8s_watch` (poll every 5 s). |
| Background tasks (Celery) | Worker crash | Celery retries (`max_retries=3`). |
**Evidence:** Code in each client’s `health` method, fallback logic in endpoints, Celery task definitions. **TRACED**.

## Security Findings
| Finding | Severity | Location | Evidence |
|---------|----------|----------|----------|
| Missing RBAC on `/metrics/*` (exposes cluster metrics to any authenticated user) | ⚠️ | `backend/app/api/v1/endpoints/metrics.py` (`list_pod_metrics`) | **FOUND** |
| Missing RBAC on `/logs/*` (any auth can read logs) | ⚠️ | `backend/app/api/v1/endpoints/logs.py` | **FOUND** |
| Exec pod endpoint forwards arbitrary shell commands without sanitisation | 🔴 | `backend/app/services/kubernetes_service.py::exec_pod` → `KubernetesClient.exec_pod` | **FOUND** |
| Scale deployment uses caller‑provided name – possible injection | ⚠️ | `backend/app/services/kubernetes_service.py::scale_deployment` (relies on `deployment_name`) | **FOUND** |
| No rate limiting on high‑frequency endpoints (`/metrics`, `/logs`) | ⚠️ | Global – not present in any middleware. | **UNVERIFIED** |
| Secrets loaded from integration records are stored unencrypted in memory; encryption only applied on write (`decrypt` used on read) – risk of exposure in logs. | ⚠️ | `integrations/*` (e.g., `gitlab_client`, `github_client`, `kubernetes_client`) | **FOUND** |
| CSRF not applicable to WebSocket (uses token auth), but HTTP endpoints lack `SameSite` cookie protection (tokens are bearer). | ⚠️ | Auth middleware (`deps.get_current_user`). | **UNVERIFIED** |

## Reliability Findings
- **WebSocket reconnection**: No exponential back‑off; rapid reconnect may overwhelm server under network flaps. (**FOUND** in `handlers.start_k8s_watch`).
- **Celery task retries** limited to 3 attempts – could leave pod sync stale after repeated failures. (**FOUND** in `tasks/sync_pods.py`).
- **Background sync for pipelines** (`sync_pipelines.py`) runs without explicit error handling – failures silent. **UNVERIFIED**.
---
## Performance Findings
- **Unpaginated pipeline list** (`list_pipelines`) defaults to page size 20 but can be called without pagination, leading to full data load – risk for large tenants. (**FOUND** in `pipelines.py`).
- **Metrics endpoint** generates synthetic time‑series for up to 60 points per request – acceptable but may increase CPU under heavy load. (**FOUND**).
- **Kubernetes watch** polls every 5 s and collects all events; may cause high API load in large clusters. (**FOUND**).
---
## Test Coverage Findings
- Only **`tests/services/investigation_test.py`** exists, covering the investigation engine – unrelated to DevOps Center.
- No unit or integration tests for:
  - Observability endpoints (`metrics.py`, `logs.py`).
  - GitOps endpoints.
  - Pipeline service.
  - Kubernetes service.
- Consequently, **test coverage for DevOps Center is 0 %** (UNVERIFIED because we did not run coverage tools).

## Contradictions
- `devopscenter.md` (the high‑level design doc) claims **all metric data is real‑time**; actual implementation falls back to synthetic data when Prometheus is unavailable (see `metrics.py`).
- The same doc states **RBAC is enforced on every feature**, yet `/metrics/*` and `/logs/*` lack role checks.
- UI shows a **"Live streaming"** badge for logs, but the fallback synthetic logs are static pre‑generated and not truly live.

## Production Readiness Gaps
1. **RBAC gaps** on metrics \& logs expose sensitive cluster data. (**Critical**)
2. **No rate limiting** – potential DoS. (**High**)
3. **Insufficient test coverage** – no automated regression guard. (**High**)
4. **WebSocket reconnection** lacks back‑off – could overload server. (**Medium**)
5. **Exec pod** endpoint allows arbitrary commands – attack surface. (**Critical**)
6. **Secret handling** – decryption occurs in‑memory; logging of raw commands may leak secrets. (**Medium**)
7. **Pagination missing** on some list endpoints (e.g., pipelines, alerts) – could cause OOM. (**Medium**)
