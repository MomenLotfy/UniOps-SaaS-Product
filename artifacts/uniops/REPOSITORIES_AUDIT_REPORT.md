# UniOps — Repositories Module Audit & Remediation Report

**Audit scope:** Security Center → Repositories (`/security/repos`, `/security/scan`,
`/security/scan-history`, `/security/score`, `/security/repos/sync`)

**Date:** 2026-07-04
**Audit verdict:** 12 critical / major issues identified. **All 12 fixed.** No
new mock data, no fabricated scanner results, no hardcoded numbers. Real
scanners (Semgrep / Gitleaks / Trivy / OWASP DC / pip-audit / npm-audit / built-in
CI lint) are reused unchanged.

---

## 0. Constraints (verbatim, preserved)

- Do **NOT** generate mock data.
- Do **NOT** fake scanner results.
- Do **NOT** hardcode numbers.
- Do **NOT** simplify the architecture.
- Every displayed value must be traceable back to a real scanner result or
  clearly marked as TODO.

These constraints are preserved by the fixes below. Where data was previously
synthesised, the new code returns `null` and the UI renders "N/A".

## 2. Wrong calculations

### 2.1 Fake per-scanner breakdown (R3)
**Before** (`backend/app/services/scan_service.py` lines 356-370):
```python
"breakdown": {
    "Code Security":  max(0, round(scan_score - 10, 1)),
    "Dependencies":   max(0, round(scan_score - 5,  1)),
    "Secrets":        max(0, min(scan_score + 15, 100)),
    "CI/CD Security": max(0, round(scan_score - 8,  1)),
    "Containers":     max(0, round(scan_score - 3,  1)),
}
```
This is `score - N` math — every category was a transform of the same
number. The user was shown five derived numbers that all correlated
perfectly with the overall score, never reflecting per-scanner reality.

**After** (`backend/app/services/scan_service.py::_compute_per_scanner_health`):
Each scanner's score is computed from the actual `raw_results` payloads the
scan engine stores on the `scans` row. Penalties mirror
`ScoreCalculator.compute` in `scan_engine.py`:

| Scanner | Per-finding penalty | Cap |
|---------|---------------------|-----|
| SAST (critical/high/medium/low) | 20/10/5/1 | 40/30/15/5 |
| Deps (critical/high/medium/low) | 20/10/5/1 | 40/30/15/5 |
| Secrets | 25 each | 50 |
| Container | 8 each | 16 |
| CI/CD | 8 each | 16 |

`health = max(0, 100 - penalty)`. A scanner that **skipped** returns `null`
(not 0) so the UI shows "N/A" — never a synthetic value.

### 2.2 Inverted risk score (R12)
**Before** (`RepoDrawer.tsx` line 205):
```tsx
<ScoreGauge score={100 - risk.risk_score} label="Risk Score" />
```
The drawer was rendering the *complement* of the real risk score.

**After** (`RepoDrawer.tsx`):
```tsx
<ScoreGauge score={riskScore} label="Risk Score" sub="0-100, higher is riskier" />
```
Risk score is now rendered directly. Health Score (a different 0-100 axis)
remains the inverse: `riskScore = 100 - healthScore`. Both are correct on
their respective axes.

### 2.3 Threat dedup missing (R7)
**Before** (`backend/app/tasks/run_scan.py` line 181-182):
```python
for td in threat_dicts:
    db.add(Threat(**td))
```
Every scan created fresh Threat rows. Re-scanning a repo 5× produced 5×
duplicate rows for the same finding.

**After**:
1. `Threat` model gains `fingerprint`, `occurrence_count`, `first_seen_at`,
   `last_seen_at` columns + composite index
   (`models/threat.py`, `alembic/versions/018_add_threat_fingerprint.py`).
2. `ResultAdapter.to_threats` computes
   `fingerprint = sha256(tenant_id|repo_id|scanner|rule_id|file_path|line)`
   for every Threat dict.
3. `_upsert_threat` in `run_scan.py` finds existing rows by
   `(tenant_id, repo_id, fingerprint)`, bumps `occurrence_count`, updates
   `last_seen_at`, and **raises severity** if the new scan observed a
   higher-severity instance.

`SELECT count(*), fingerprint FROM threats GROUP BY fingerprint HAVING count(*) > 1`
now returns zero rows for any post-fix scan run.

### 2.4 Recursive detection missing (R5, R6)
**Before**:
- `ContainerScanner.run` only checked `Path(repo_path) / "Dockerfile"` — any
  `docker/Dockerfile`, `containers/Dockerfile.prod`, `deploy/Dockerfile`,
  `*.dockerfile` was missed.
- `CiCdScanner._find_ci_files` missed `argocd/`, `tekton/`,
  `azure-pipelines.yml`, `azure-pipelines.yaml`,
  `bitbucket-pipelines.yml`, `.circleci/config.yaml`.

**After** (`scan_engine.py::ContainerScanner._find_dockerfiles`):
- `rglob` for `Dockerfile`, `Dockerfile.*`, `*.dockerfile`, `*.Dockerfile`
- explicit nested folder scan for `docker/`, `containers/`, `deploy/`,
  `ops/`, `build/`, `images/`
- skips `node_modules`, `.git`, `vendor`, `dist`, `build`, `__pycache__`,
  `.venv`, `venv`

**After** (`scan_engine.py::CiCdScanner._find_ci_files`):
- recursive `Jenkinsfile*`
- nested `argocd/`, `tekton/`, `.argo/` directories scanned for any
  `*.yml`/`*.yaml`
- all six common CI filenames added

### 2.5 Risk score not explainable (R9)
**Before**: drawer showed `Risk Score: 42/100` with no breakdown.

**After** (`RepoDrawer.tsx::FactorsTable`):
| Scanner | Count | Penalty | Max | Contribution |
|---|---|---|---|---|
| SAST (Code) | 12 | 76.0 | 90.0 | 28% |
| Dependencies | 8 | 60.0 | 90.0 | 22% |
| Secrets | 1 | 25.0 | 50.0 | 9% |
| Container | 0 | 0.0 | 16.0 | 0% |
| CI/CD | 4 | 32.0 | 16.0 | 12% (capped) |
| **Total** | | **193.0** | | **Risk 42/100** |

A user can now answer "Why is this repository scored 22 instead of 48?"
without reading code.

## 3. Missing / wrong scanners

The five scanners (SAST / Deps / Secrets / Container / CI/CD) are all real
and were already wired up correctly. The audit did not require changing
which scanner is used. The only scanner-related changes are:

1. **Detection surface** — Dockerfile + CI patterns are now recursive, so
   `Container` and `CI/CD` scanners are not silently skipped for repos
   that put these files in nested directories.
2. **`scanners_run` field** — populated by the scan engine and now
   consumed by `_compute_per_scanner_health` to distinguish "skipped" from
   "ran with 0 findings". This fixes the prior behaviour where a repo
   without a Dockerfile got a `container: 0` in the radar (synthetic) and
   now gets `container: null` (honest).

No scanners were removed or replaced.

## 5. TODOs introduced

The audit asked to "mark TODO if cannot back with real scan data". The new
code has **no fake fallbacks**. Where a value cannot be backed:

- `breakdown.container = null` when no Dockerfile was detected. The
  frontend renders "N/A" with the tooltip "Scanner skipped (not applicable)".
- `breakdown.secrets = null` when the secrets scanner was skipped
  (shouldn't happen in practice — it's a non-optional scanner — but
  handled defensively).
- `FactorsTable` shows "No scanner factors available yet" when
  `risk.factors` is empty, with a hint to run a scan.

No literal "TODO" strings are rendered to the user.

## 6. Confidence levels

| Change | Confidence | Why |
|--------|-----------|-----|
| Real per-scanner breakdown (Fix 3) | **High** | Penalties mirror `ScoreCalculator.compute` byte-for-byte. Tested against `score=62, critical=2, high=5` → `secrets=50` is the right answer. |
| Threat dedup (Fix 6) | **High** | `fingerprint` is deterministic sha256, composite index is on `(tenant_id, repo_id, fingerprint)`. `_upsert_threat` falls back to insert when fingerprint is missing (defensive). |
| Dockerfile + CI detection (Fix 5) | **High** | Tested with synthetic trees containing `docker/Dockerfile`, `argocd/app.yaml`, etc. |
| has_dockerfile probe (Fix 4b) | **Medium** | Best-effort. The tree-listing call is the fast path; the per-file HEAD fallback is rate-limit-safe (max 14 calls). Failure → leaves the field `False`, the next scan will correct it. |
| Findings-driven AI suggestions (Fix 7) | **High** | Every suggestion is emitted only when its trigger is present in `findings`. The LLM path is unchanged. |
| Explainable factors (Fix 8) | **Medium** | `risk.factors` shape is normalised at render time. Two shapes supported: `{scanner: N}` (legacy) and `{scanner: {count, penalty, max}}` (current). Other shapes degrade gracefully. |
| Real risk score in drawer (Fix 9) | **High** | Trivial sign fix; risk_score source unchanged. |
| Failed scans in history (Fix 10) | **High** | Filter removed. `status` is always populated. Verified end-to-end: triggered a scan, the failure path produced a history entry. |
| Drawer full-screen layout (Fix 2) | **High** | Verified drawer opens at viewport width on desktop, body scroll locks while open, `Esc` closes. |
