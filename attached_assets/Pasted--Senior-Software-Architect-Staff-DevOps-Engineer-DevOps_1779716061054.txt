أنت Senior Software Architect + Staff DevOps Engineer مسؤول عن إعادة تصميم نظام DevOps Center داخل UniOps وتحويله من Monolithic Architecture إلى Scalable Distributed Event-Driven Platform.

---

🚨 الوضع الحالي (مشاكل مؤكدة في النظام)

النظام الحالي يحتوي على:

- Frontend Monolith (DevOpsCenter 1000+ lines)
- Backend FastAPI يحتوي Kubernetes + CI/CD + GitHub + DB logic معًا
- Celery jobs تعمل sync شامل لكل شيء
- Frontend يعتمد على polling (5s / 15s)
- Mixed responsibilities داخل نفس الخدمات
- Missing or broken endpoints (مثل cancel pipeline → 404)
- Tight coupling بين UI + backend + external APIs

---

🎯 الهدف

تحويل النظام بالكامل إلى:

Frontend
↓
API Gateway (Control Plane)
↓

| Kubernetes Service              |
| CI/CD Service                  |
| Observability Service          |

↓
Event Bus (Redis Streams / Kafka)
↓
Workers (Celery consumers / event processors)
↓
Database (PostgreSQL per domain)

---

🧱 المطلوب إعادة تصميمه بالكامل

---

1. API Gateway (Control Plane)

أنشئ طبقة واحدة فقط مسؤولة عن:

- Authentication / Authorization
- Tenant isolation
- Routing requests إلى services
- Aggregation فقط (NO business logic)
- Rate limiting + logging

Endpoints example:

- /api/k8s/*
- /api/cicd/*
- /api/observability/*

ممنوع وجود Kubernetes أو CI/CD logic داخل الـ gateway.

---

2. Domain Services Separation

🟦 Kubernetes Service

مسؤول فقط عن:

- Pods
- Deployments
- Scaling
- Logs
- Exec
- Events

ممنوع أي CI/CD logic داخله.

---

🟨 CI/CD Service

مسؤول فقط عن:

- Pipelines
- Jobs
- Builds
- Reruns
- GitHub/GitLab integration

ممنوع أي Kubernetes calls داخله.

---

🟪 Observability Service (إن وجد)

مسؤول عن:

- Metrics
- Logs aggregation
- Alerts
- Monitoring

---

3. Event Bus Layer (Redis Streams أو Kafka)

استبدل Celery monolithic jobs بـ event-driven system.

Events:

- pod.created
- pod.deleted
- pipeline.started
- pipeline.failed
- deployment.scaled

كل service تنشر وتستهلك events.

---

4. Workers Layer (Consumers)

أنشئ workers مستقلة:

- k8s-event-worker
- cicd-event-worker
- observability-worker

كل worker:

- يستهلك events فقط
- يحدث database فقط
- لا يتواصل مباشرة مع frontend

---

5. إزالة Polling بالكامل (CRITICAL)

قم بإزالة:

- usePods polling (15s)
- usePipelines polling (15s)
- usePodLogs polling (5s)

واستبدلها بـ:

WebSockets + Event Streams

---

6. WebSocket Layer (Real-time UI)

أنشئ WebSocket channels:

- /ws/k8s/pods
- /ws/k8s/logs
- /ws/cicd/pipelines

Frontend يجب أن:

- يستقبل updates مباشرة
- لا يقوم بأي polling
- يعتمد على event-driven updates فقط

---

7. Frontend Refactor

قسّم DevOpsCenter monolith إلى modules:

/modules/kubernetes
/modules/cicd
/modules/observability

كل module يحتوي على:

- isolated hooks
- isolated API client
- isolated state store

ممنوع global shared state بين domains.

---

8. Fix Critical Bugs أثناء إعادة التصميم

Fix 1:

cancel pipeline endpoint (404)
→ implement missing API in CI/CD service

---

Fix 2:

mixed pipeline services (duplicate logic)
→ merge into single CI/CD service

---

Fix 3:

wrong state handling in UI
→ separate:

- disconnected
- empty state
- error state
- loading state

---

9. Database Isolation

افصل البيانات حسب domain:

- k8s_* tables
- cicd_* tables
- observability_* tables

كل service يمتلك schema مستقل.

---

10. Observability & Logging

أضف structured logging لكل service:

- request_id
- tenant_id
- event_type
- service_name
- latency
- error traces

---

11. Final Target Architecture

Frontend
↓
API Gateway
↓

| K8s Service                    |
| CI/CD Service                 |
| Observability Service         |

↓
Event Bus (Redis/Kafka)
↓
Workers (Consumers)
↓
PostgreSQL (per domain)
↓
WebSockets → Frontend (real-time updates)

---

🎯 Final Outcome Requirements

بعد التنفيذ:

- لا يوجد polling نهائيًا
- كل updates real-time
- كل domain isolated بالكامل
- لا يوجد shared business logic بين services
- النظام قابل للتوسع أفقيًا (horizontal scaling)
- إضافة AWS/GCP/Azure يكون plug-and-play
- UI يصبح reactive event-driven dashboard

---

🚨 Definition of Done

النظام يعتبر ناجح فقط إذا:

- حذف polling بالكامل
- WebSockets تعمل 100%
- كل service تعمل independently
- لا يوجد monolith backend logic
- كل event يتم تمريره عبر event bus
- UI يعرض data real-time بدون refresh
